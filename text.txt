# Building a Reliable Command Line Tool

A command line tool should be simple to use, easy to understand, and predictable even when something goes wrong. Good error messages are very important because users need to understand what happened without reading the source code, and a well-designed command line interface can make a very complicated program feel surprisingly simple.

The first version of this tool was written very quickly, and the implementation is still changing as new requirements appear.

When designing the command line interface, we should avoid adding options that are only useful in rare situations, because every additional option increases the amount of documentation that users have to read and makes the interface more difficult to remember.

A useful tool should also provide enough information for users to diagnose problems by themselves. In particular, an error should explain what went wrong, where it happened, and what the user can do to fix it.
